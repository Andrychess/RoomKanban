# RoomKanban — Задачи офиса

**RoomKanban** (папка проекта: `OficceHelper`) — настольное приложение на **Electron** для небольшой команды: канбан-доска, сроки, файлы, обмен документами между сотрудниками. Все данные комнаты лежат в **одной папке**, которую вы сами выбираете: локальный диск, общая сетевая папка, флешка, OneDrive, Яндекс.Диск и т.п.

Сервер не нужен: синхронизация — это общий доступ к файлам + отслеживание изменений на диске.

## Возможности

| Область | Что умеет приложение |
|--------|----------------------|
| **Комнаты** | Создание комнаты в выбранной папке, вход по списку сотрудников (без саморегистрации), несколько недавних комнат |
| **Канбан** | 4 колонки: Входящие → В очереди → В работе → Готово; перетаскивание; смена этапа на карточке |
| **Задачи** | Название, описание, вид и приоритет, ответственный, срок, чек-лист, комментарии, история изменений |
| **Файлы** | Входящие материалы и итоговые документы к задаче (копируются в папку комнаты) |
| **Фильтры и поиск** | По приоритету, виду, «мои / чужие», текстовый поиск по названию, описанию, сотруднику |
| **Календарь** | Просмотр задач по срокам |
| **Команда** | Начальник добавляет сотрудников; пароли на комнату и на учётки |
| **Начальник** | Сводка (нагрузка, просрочка, «зависшие»), отчёт «Просрочено», шаблоны задач, настройка меток |
| **Архив** | Готовые задачи убираются с доски, но сохраняются с файлами |
| **Обмен** | Отдельное «окно» файлов для каждого сотрудника; любой может положить файл коллеге |
| **Блокировка** | Одновременное редактирование одной задачи ограничено (файл блокировок в `sync/`) |
| **Тема** | Светлая и тёмная тема, сохраняется на этом ПК |

## Требования

- **ОС:** Windows 10/11 (основная целевая платформа; Electron кроссплатформенный, но тестировалось под Windows)
- **Node.js:** 18+ (для разработки и сборки)
- **Доступ к папке комнаты:** чтение и запись для всех участников; для сети — стабильная общая папка без длительных конфликтов блокировки облака

## Сборка

### Только собрать код (без установщика)

```bash
npm install
npm run build
npm run preview
```

Папка `out/` — готовое приложение для проверки на этом ПК (`preview` запускает Electron с `out/`).

### Установщик Windows (.exe)

Нужны **Node.js 18+** и интернет (первый раз скачается Electron).

```bash
cd OficceHelper
npm install
npm run dist
```

Результат в папке **`release/`**:

| Файл | Назначение |
|------|------------|
| `Задачи офиса Setup 0.1.0.exe` | Установщик для раздачи сотрудникам |
| `win-unpacked/` | Портативный вариант без установки (`Задачи офиса.exe` внутри) |

Только распакованная папка без NSIS (быстрее для проверки):

```bash
npm run dist:dir
```

### Установка на компьютер сотрудника

1. Скопируйте **`Задачи офиса Setup …exe`** на ПК (флешка, сеть, почта).
2. Запустите установщик → при необходимости укажите папку → «Установить».
3. Ярлык появится в меню «Пуск» и (по умолчанию) на рабочем столе.
4. При первом запуске: **Открыть комнату** или **Создать комнату** → укажите **общую папку** комнаты (сетевой путь или синхронизируемая папка).

Данные комнаты **не** входят в установщик — они всегда в выбранной вами общей папке. На каждом ПК ставится только программа; папку комнаты все используют одну и ту же.

### Портативный запуск (без установки)

Скопируйте целиком папку `release/win-unpacked` на диск или флешку и запускайте **`Задачи офиса.exe`**. В реестр ничего не пишется.

### Обновление версии

Соберите новый установщик (`npm run dist`), на ПК сотрудников запустите новый Setup поверх старой версии (или удалите старую через «Программы и компоненты» и установите заново). Папку комнаты трогать не нужно.

## Быстрый старт

### 1. Первый запуск (начальник)

1. Запустите приложение.
2. **Первый запуск** или **Создать комнату** → укажите папку (создайте, например, `D:\Офис\КомнатаЗадач` или подключите сетевой диск).
3. Введите название комнаты, **ваше имя и должность** (вы станете начальником).
4. При желании задайте пароль на комнату и пароль своей учётки.
5. Откроется канбан — можно создавать задачи.

### 2. Подключение сотрудника

1. Начальник в разделе **Сотрудники** добавляет людей (имя + роль).
2. Все используют **одну и ту же папку** комнаты (сеть / облако с синхронизацией).
3. Сотрудник: **Войти в комнату** → та же папка → **выбрать своё имя** из списка (не «регистрация», а выбор профиля).
4. При необходимости вводит пароль комнаты и/или личный пароль.

### 3. Общая папка

Скопируйте путь к папке комнаты или дайте доступ к сетевой шаре. Код приглашения (`invite_code`) хранится в `room_state.json` — для справки, вход идёт через выбор папки и сотрудника.

## Роли: начальник и сотрудники

| Действие | Начальник | Сотрудник |
|----------|-----------|-----------|
| Создавать и редактировать задачи | ✓ | ✓ |
| Менять этап (колонку) | ✓ | ✓ |
| Добавлять комментарии | ✓ | ✓ |
| Добавлять/забирать файлы в **Обмен** | ✓ | ✓ |
| Добавлять сотрудников, пароли | ✓ | — |
| Настройка видов задач и приоритетов | ✓ | — |
| Шаблоны задач (редактирование списка) | ✓ | использует при создании |
| Сводка, «Просрочено», напоминания (настройка) | ✓ | — |
| Архив (просмотр, восстановление) | ✓ | ✓ |

Начальник определяется полем `chief_pc` в `room_state.json` (ключ сотрудника `emp_…`, создавший комнату).

## Разделы приложения

После входа в комнату доступны вкладки (и пункты меню **Вид**):

| Вкладка | Назначение |
|---------|------------|
| **Задачи** | Канбан-доска |
| **Сроки** | Календарь по датам выполнения |
| **Сотрудники** | Состав комнаты, пароли (начальник управляет списком) |
| **Обмен** | Файлы «для каждого сотрудника» отдельным окном |
| **Архив** | Задачи, убранные с доски из колонки «Готово» |
| **Сводка** | Только начальник: метрики, нагрузка, напоминания |
| **Просрочено** | Только начальник: список просроченных задач |

В шапке: название комнаты, «Вы: …», переключатель **светлой/тёмной** темы, **Другая комната**.

**Меню приложения**

- **Комната** — сменить/создать комнату, закрыть текущую.
- **Вид** — календарь, состав, просрочено, сводка, архив, обмен; масштаб и инструменты разработчика.

Горячие клавиши (меню): `Ctrl+Shift+C` — календарь, `Ctrl+Shift+T` — сотрудники, `Ctrl+Shift+O` — просрочено, `Ctrl+Shift+D` — сводка.

## Канбан и задачи

### Колонки

| Код в данных | На доске | Полное название |
|--------------|----------|-----------------|
| `review` | Входящие | На рассмотрении |
| `todo` | В очереди | К выполнению |
| `in_progress` | В работе | В работе |
| `done` | Готово | Выполнено |

### Карточка задачи

- **Приоритет** и **срок** (просроченные подсвечиваются).
- **Вид задачи** (метка с цветом, настраивается начальником).
- Краткое **описание**, прогресс **чек-листа**.
- Ссылки на прикреплённые файлы.
- Выпадающий список **этапа** и кнопка **Подробнее**.

### Редактор задачи

- **Описание** — постоянный текст задачи (ТЗ).
- **Комментарии** — отдельная лента; можно писать, даже если карточку сейчас редактирует другой (блокировка не мешает комментариям).
- **Чек-лист** — пункты с галочками.
- **Документы** — блоки «к задаче» (входящие) и «итоговые».
- **История изменений** — кто и что менял (создание, этап, срок, файлы и т.д.).

### Создание задачи

- Кнопка **+ Новая задача** или **+** в заголовке колонки.
- При создании можно выбрать **шаблон** (если начальник настроил шаблоны).
- **Шаблоны** (начальник): кнопка на канбане → список шаблонов с названием задачи и смещением срока «+ N дней».

### Фильтры

Сворачиваемая панель **Показать фильтр**:

- срочность (приоритет);
- вид задачи;
- все / только мои / чужие;
- **поиск** по тексту.

### Сортировка в колонке

В каждой колонке — выбор сортировки (по сроку, приоритету, дате обновления и т.д.). Порядок хранится **на этом компьютере** в настройках приложения, не в папке комнаты.

### Готово → Архив

В колонке **Готово** кнопка **В архив** переносит все выполненные задачи в архив (файлы не удаляются). Восстановление — вкладка **Архив** → **Вернуть на доску**.

### Одновременное редактирование

При открытии задачи на редактирование ставится **блокировка** (~3 минуты, продлевается автоматически). Другой пользователь видит сообщение «Сейчас редактирует: …» и не может сохранить изменения полей задачи (комментарии — можно). Смена этапа перетаскиванием **не** требует блокировки.

## Обмен файлами

Раздел **Обмен** — сетка карточек по **каждому сотруднику** комнаты.

- **+ Добавить файл** в окне сотрудника — положить ему документ (письмо, скан, таблицу).
- Имя файла — клик, открыть в системе.
- **×** — удалить один файл.
- **Очистить** — удалить все файлы в этом окне (с подтверждением).
- Своё окно выделено рамкой («это вы»).

Данные общие для всех ПК с той же папкой комнаты; обновление списка — автоматическое при изменении файлов в `sync/exchange/`.

## Безопасность и пароли

Пароли хранятся как **хэш scrypt** (соль + хэш), не в открытом виде.

| Пароль | Где задаётся | Зачем |
|--------|--------------|--------|
| На комнату | Сотрудники → начальник | Чтобы посторонний с доступом к папке не вошёл в приложение |
| На учётку сотрудника | Сотрудники → начальник | Личный вход под выбранным именем |

Самостоятельной регистрации нет: начальник создаёт записи сотрудников, при входе человек **выбирает имя** из списка.

## Напоминания о сроках

Настраиваются начальником в **Сводка → Напоминания о сроках**:

- за сколько дней до срока напоминать (например `1, 3`);
- уведомлять ответственного и/или начальника.

Показываются **системные уведомления Windows** на том ПК, где открыта комната (проверка примерно раз в 5 минут). Учтите: ответственный получит уведомление только на своём компьютере, если у него тоже запущено приложение с этой комнатой.

## Тема оформления

Кнопка в шапке: **☀ Светлая** / **☾ Тёмная**.

- По умолчанию — тёмная.

## Структура папки комнаты

Все пути относительно **выбранной пользователем папки** (корень комнаты):

```
Комната/
├── .room/                          # служебная метка (при создании)
├── docs/
│   ├── <task_id>/
│   │   ├── source/                 # входящие файлы задачи
│   │   │   └── <fileId>_<имя>
│   │   └── completed/              # итоговые файлы
│   │       └── <fileId>_<имя>
│   └── exchange/
│       └── <employee_key>/         # файлы в «окне» сотрудника
│           └── <fileId>_<имя>
└── sync/
    ├── room_state.json             # комната, сотрудники, начальник, пароли
    ├── tasks/                      # одна задача = один JSON (task_<id>.json)
    ├── exchange/                   # обмен: <employee_key>.json на сотрудника
    ├── history/                    # журнал: <task_id>.json на задачу
    ├── task_types.json             # виды задач (метки)
    ├── task_priorities.json        # приоритеты
    ├── task_templates.json         # шаблоны для новых задач
    ├── task_locks.json             # кто редактирует задачу (временные блокировки)
    ├── reminder_settings.json      # настройки напоминаний (в папке комнаты)
    ├── board.json.migrated         # бывший board.json (после авто-миграции)
    ├── exchange.json.migrated      # бывший exchange.json
    ├── task_history.json.migrated  # бывший общий журнал
    └── pc_*.json                   # устаревшее; мигрирует в sync/tasks/
```

### Кратко о ключевых файлах

**`room_state.json`**

```json
{
  "room_id": "...",
  "room_name": "Название",
  "invite_code": "123456",
  "chief_pc": "emp_...",
  "employees": {
    "emp_abc": {
      "name": "Иван",
      "role": "Менеджер",
      "joined_at": 1710000000,
      "password": { "salt": "...", "hash": "..." }
    }
  },
  "room_password": { "salt": "...", "hash": "..." }
}
```

**`sync/tasks/<task_id>.json`** — одна задача. Основные поля:

| Поле | Описание |
|------|----------|
| `id` | `task_…` |
| `title`, `description` | Название и описание (`comment` в старых данных читается как описание) |
| `status` | `review` \| `todo` \| `in_progress` \| `done` |
| `type_id`, `priority_id` | Ссылки на справочники |
| `assignee_pc` | Ключ сотрудника-ответственного |
| `due_date` | `YYYY-MM-DD` или `null` |
| `source_files`, `completed_files` | Вложения |
| `comments`, `checklist` | Комментарии и чек-лист |
| `archived_at` | `null` — на доске; число (unix sec) — в архиве |
| `created_by_pc`, `created_at`, `updated_at` | Мета |

## Настройки приложения

Файл: **`%APPDATA%\room-kanban\settings.json`** (каталог `userData` Electron).

| Поле | Назначение |
|------|------------|
| `theme` | `light` \| `dark` |
| `currentRoomPath` | Последняя комната (автооткрытие при запуске) |
| `lastOpenedRooms` | Список недавних путей |
| `machineFingerprint` | Идентификатор ПК |
| `employeeBindings` | Путь комнаты → последний выбранный `emp_…` на этом ПК |
| `kanbanColumnSort` | Сортировка колонок по пути комнаты |
| `reminderSent` | Уже отправленные напоминания (чтобы не дублировать) |

Эти настройки **личные для компьютера**, не синхронизируются через папку комнаты.

## Как устроена синхронизация

1. **Нет центрального сервера** — источник правды: JSON-файлы и папка `docs/` в общей директории.
2. **Main-процесс** Electron следит за папками **`sync/tasks/`**, **`sync/exchange/`** и отдельными справочниками (`task_types.json` и т.д.) через **chokidar**.
3. При изменении одного файла задачи или обмена перечитывается только он — правки разных задач с двух ПК не перезаписывают друг друга.
4. При первом открытии комнаты старые **`board.json`**, **`exchange.json`**, **`task_history.json`** автоматически разбиваются на отдельные файлы (оригиналы переименовываются в `*.migrated`).
5. **Запись JSON** — через временный файл и `rename` (`writeJsonFileAtomic`), чтобы реже попадать на «обрезанный» JSON при чтении во время sync.
6. **Очередь операций** (`AsyncMutex`) в каждом store на одном ПК — нет гонки «два быстрых сохранения подряд» в одном процессе.
7. **Слияние одной задачи** — при записи `sync/tasks/<id>.json` с диска подставляется версия с большим `updated_at`, если она новее локальной (кроме явного «сохранить поверх» в редакторе).
8. **Блокировка редактирования** (`task_locks.json`) — мягкая защита от одновременного редактирования одной карточки в форме.
9. После **своей** записи watcher на ~600 мс игнорируется, чтобы не дублировать обновление UI.
10. **Сетевые пути** (UNC `\\…`, OneDrive и т.п.) — увеличенный `stabilityThreshold` у chokidar, чтобы дождаться окончания записи файла облаком/SMB.
11. **Уведомление в интерфейсе** — при изменении данных с другого ПК показывается всплывающее сообщение (`room-sync-updated`).
12. **«Обновить синхронизацию»** — в панели комнаты: принудительно перечитать задачи, обмен, виды, приоритеты и шаблоны с диска.
13. **Конфликт при сохранении задачи** — если с момента открытия редактора на диске появилась более новая версия (`client_base_updated_at`), предлагается взять версию с диска или сохранить свои правки поверх.

Ограничение: при одновременной правке **одной и той же** задачи с двух ПК без открытого редактора побеждает версия с более поздним `updated_at` (без построчного merge полей). В открытом редакторе конфликт можно разрешить вручную.

## Рекомендации по развёртыванию в офисе

1. **Одна папка комнаты** на общий ресурс (например `\\server\share\RoomKanban` или синхронизируемая папка OneDrive с полными правами для отдела).
2. Убедитесь, что **антивирус** не блокирует запись в `sync/` и `docs/`.
3. Обучите сотрудников: вход = **выбор папки + выбор имени**, не копирование папки `sync/` вручную.
4. Начальник периодически смотрит **Сводку** и **Просрочено**; готовые задачи — **В архив**, а не бесконечное накопление в «Готово».
5. Для обмена черновиками между людьми используйте **Обмен**, для задач с этапами — **канбан**.
6. Резервное копирование: достаточно **копировать всю папку комнаты** (Time Machine, Veeam, robocopy по расписанию).

## Ограничения и известные особенности

- Нет веб-версии и мобильного клиента — только десктоп Electron.
- Нет встроенного чата и push на телефон — только уведомления Windows на открытом приложении.
- Сортировка колонок канбана — **per-PC**, не общая.
- Смена этапа drag-and-drop не проверяет блокировку редактирования.
- При агрессивной синхронизации облака (конфликтующие копии файлов) возможны задержки или редкие сбои чтения JSON — предпочтительна стабильная SMB-шара или один аккаунт облака с нормальной синхронизацией.
- Удаление сотрудника из комнаты не переназначает автоматически его задачи (проверьте ответственных заранее).
